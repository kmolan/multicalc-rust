# Motion accuracy

_Table below generated by `cargo run -p multicalc-qa --bin gen_accuracy_tables`; do not edit it by hand._

Minimum-snap trajectories. The generator solves the same problem a different way, through the full
constrained system with its multipliers — so matching coefficients mean two independent routes agree.

Each segment is a degree-7 curve in its own time `τ ∈ [0, 1]`. What is minimised is the total snap —
the fourth derivative of position, squared and added up along the path — subject to the path going
where it was told:

```
minimise  cᵀHc    subject to  C·c = b
```

`c` holds every segment's eight coefficients. `H` is block-diagonal, one `Dᵢ⁻⁷ · Q` per segment, with
the same fixed 8×8 throughout:

```
Q[j][k] = j(j−1)(j−2)(j−3) · k(k−1)(k−2)(k−3) / (j + k − 7)     for j, k ≥ 4,  else 0
```

Everything below the fourth power is zero because nothing lower survives four differentiations.
`C·c = b` collects the requirements: position at both ends of every segment, velocity, acceleration
and jerk matched across every joint and pinned at the two ends of the path.

multicalc substitutes out the values already known and solves only for the `3(M − 1)` left free.
The generator keeps all `8M` unknowns and solves the whole thing with its multipliers:

```
[[2H, Cᵀ], [C, 0]] · [c; λ] = [0; b]
```

That larger system is worse conditioned, which is why the coefficients are compared more loosely than
the positions and velocities they produce.
