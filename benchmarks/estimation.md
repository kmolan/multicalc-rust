# Estimation accuracy

_Table below generated by `cargo run -p multicalc-qa --bin gen_accuracy_tables`; do not edit it by hand._

Every row runs a fixed measurement sequence through predict/update and compares the final state,
covariance, innovation, and innovation covariance against
[FilterPy](https://github.com/rlabbe/filterpy), the reference Python Kalman library, which defaults
to the same Joseph-form covariance update multicalc does. The rows cover a curved motion model and a
sensor that reads the state through a curve, then run each again through the unscented filter, which
samples the model at a spread of points rather than differentiating it. A filter run compounds
per-step error, so every tolerance is looser than a single-operation factorization's, and looser
again at the shipped spread of 1e-3, where the middle point carries a weight near −10⁶ and the
rebuilt covariance is a difference of large nearly-equal numbers. That is the cost of the default
spread, not a weakness in the filter; the wider-spread row holds the usual bound.

In the equations, `x` is the state vector, `u` the control input, and `x⁻` the predicted state.
`F` is the state-transition matrix (`x⁻ = F·x`), `H` the measurement model mapping state to
measurement, and `h` its nonlinear counterpart (`z = h(x)`). `f` is the matching counterpart on the
prediction side (`x⁻ = f(x)`), used where the motion itself curves: the coordinated-turn rows carry
the state `[x, y, θ, v, ω]` (position, heading, forward speed, and turn rate) one tick along a
turning arc. `α` is the unscented filter's spread setting.
